# Whole-system audit, 2026-10-21

Four read-only reviews (rules and data layer, admin, public site and intake, portal and auth).
No patient-to-patient data leak, no signed-out PHI read, no role exceeding its powers, and no
intake field the rules would refuse. Lint, `npm run check` and the build pass. The rules tests
were not run (Java isn't installed on this machine).

✔ = confirmed by hand in the code, not only by a reviewer.

## Fix first (planned for 2026-10-22)

1. ✔ **Invite email can be abused for phishing.** The invite template takes `{{subject}}`,
   raw `{{{message_html}}}` and `{{setup_link}}` from the browser, and the EmailJS service,
   template and public key ship in the bundle (`src/lib/emailjs.js`,
   `src/admin/patients/portalStore.js:60-65`, `docs/client-portal.md` "EmailJS setup").
   Anyone can send CorePhia-branded mail from `info@corephia.com` with any text and link.
   Fix: make the invite template fixed text whose button is built in the template from
   `chartId` and `inviteId` on a hard-coded `https://corephia.com/portal/setup` (change the
   template in the EmailJS dashboard too), or send invites from a server. While there, build
   the link from a fixed origin rather than `window.location.origin` (an invite sent from
   localhost or a preview channel links there).
2. ✔ **Offline notes are lost.** Firestore uses the default memory-only cache (no
   `persistentLocalCache` anywhere). A draft queued offline is dropped when the tab closes or
   idle sign-out unmounts the admin, though the editor says it will save
   (`NoteEditor.jsx:316-333, 356-362`). Signing offline never settles, so the editor is stuck
   on "Signing…" (`NoteEditor.jsx:364-384`; Close has an 8 s timeout, sign has none).
   Fix: `initializeFirestore` with `persistentLocalCache` for the admin, and a timeout on sign.
   Related: a draft on an inactive chart opens editable, then saves fail with "signed or
   discarded somewhere else" (`PatientChart.jsx:617`); open it read-only with only Discard.
   Related: a failed autosave is never retried before idle sign-out.
3. ✔ **Membership link previews are broken.** `scripts/prerender.mjs:47-52` puts the
   description in with `` `$1${description}` ``; "$199" is read as group `$1` + "99", so
   `dist/membership.html` og:description and twitter:description are garbage. Use function
   replacers (or `split/join`) for og/twitter title and description, and add a prerender
   assert that og:description equals the meta description.
4. ✔ **GA could count the intake or portal.** `src/lib/googleAnalytics.js` sets the
   `ga-disable-…` flag in an effect plus `setTimeout 0`, after React Router has already
   called `pushState`. If GA's "page changes based on browser history events" is on, a click
   on "Get started" records `/intake`. Fix: set the flag from the destination path before
   `pushState`/`replaceState` run (wrap them), so it's safe whatever the console setting.
5. **Invites outlive discharge, and old invites aren't revoked.** `isOwnInviteLink` and the
   invite `get` rule (`firestore.rules` ~380-397, ~580) never check the chart's status;
   "Resend invite" leaves earlier `sent` invites live for 7 days; the early return in
   `linkInvite` leaves a second invite `sent`. Fix: require an active chart and
   `getAfter(invite).status == 'used'` in the rules; mark earlier invites `superseded`.
   Add rules tests.
6. **Deleting an admitted applicant's intake orphans the chart.** `firestore.rules:363`
   lets the super admin delete any intake; Delete shows for every status
   (`Applicants.jsx:52`). Afterwards Make inactive fails (`chartStore.js:120` updates a missing
   doc), invites and appointments are refused. Fix: rules refuse the delete when
   `patients/{id}` exists; hide Delete then; only update the intake in `setApplicantStatus`
   when it exists.
7. **A mistyped vital in a signed note stays in the portal forever.** Note vitals are an
   unchecked map (`firestore.rules` ~441-454), copied to `progress/visit-{noteId}` on sign,
   and staff can't remove that entry. `NumberField` (`NoteEditor.jsx:54`) has no min/max.
   Fix: range-check vitals in `isNoteShape` and the field (weight 50-800 like home
   weigh-ins), and add a staff `removed: {by, at}` path for visit entries.
8. **Copy that contradicts the Terms or the code** (decisions for Louie and the client):
   - ✔ `Legal.jsx:19` says visit counts never run on the intake, but
     `PatientIntakeForm.jsx:478-482` counts "opened". Drop the count or reword the policy.
   - ✔ `PricingSection.jsx:92` says "Cancel anytime"; the Terms say cancellation is confirmed
     at enrollment and the policy is still open.
   - The intake offers every state and never says Florida only (`intakeScreens.jsx:12-18`).
     Add an early "Are you in Florida?" screen or a notice under State.

## Worth fixing (done 2026-10-21)

- Program and Membership heroes: `<Reveal eager>` / `useReveal(true)` start shown in the
  prerendered HTML; `prerender.mjs` fails the build if an `<h1>` sits in a hidden Reveal.
- Admit/Decline race: `setApplicantStatus` is a transaction (reads chart and intake), and
  skips the intake update when the intake was deleted.
- Stale chunks: `main.jsx` reloads once on `vite:preloadError`; HTML is `no-cache` in
  `firebase.json` (check with `curl -I` after deploying).
- Staff messages can be removed from the patient's view (author, or co-admin and up). New
  messages carry `removed: false`; the patient's query filters on it, so **messages written
  before this have no `removed` field and no longer show in the portal** (test data only).
  Rules `isMessageRemoval`, 3 new rules tests.
- `Modal` takes `dirty`: New message and Post update ask "Discard what you wrote?". The
  ConfirmDialog scrim no longer closes it mid-action.
- Calendar Month: the day panel falls back to a day in the month on screen.
- `/portal/reset` "Send a new link" returns to the expired link's own destination.
- Found on the way: `getDemoStore` built two stores when called twice at load, so demo
  conversations showed no messages. It now caches the promise.
